# Contributing to ClearCut

Thank you for helping build ClearCut.

## Before opening a change

1. Read the [product brief](docs/01-product-brief.md) and [technical brief](docs/02-technical-brief.md).
2. Check the backlog in [docs/06-roadmap.md](docs/06-roadmap.md).
3. Keep confidential scripts, credentials, and real legal correspondence out of the repository.
4. Prefer a small, testable change with a clear domain boundary.

## Pull requests

Describe the user problem, implementation, tests, security impact, and documentation changes. UI changes should include a screenshot or short recording.

## Product boundary

ClearCut is a rights-clearance research and workflow assistant. Contributions must not turn research output into an unsupported legal conclusion or remove the human approval boundary for consequential actions.
